# WS-P2.1 — Adversarial architecture review and resolutions (AC-012)

**Date:** 2026-07-11
**Reviewed design:** `2026-07-11-wsp21-recovery-controls-drills-design.md` (v1 → revised to v2)
**Gate:** AC-012 — adversarial architecture review before implementation; findings resolved in the approved design.
**Verdict on v1:** APPROVABLE-WITH-CHANGES — 3 blockers, 8 majors, plus minors. All resolved in v2 (this document records each finding and its resolution). The v2 design's reworked AC-002/AC-003 detection path was re-reviewed (see §Re-review).

## Root cause

Every blocker traced to one v1 mistake: **conflict detection ran inside the observation-ingest DB transaction.** That is wrong because (a) a rejected ingest (digest mismatch) rolls back any condition written first; (b) deployment split-brain is not knowable at ingest (the post-deploy unit is created `SUBMITTED` in the same transaction, and `_validated_subject` hard-rejects a non-`COMPLETED` bound unit); (c) write-once observation semantics (`unique(source_system, source_reference, fact_hash)` with `observed_at` in the fact identity) make the runner's re-push either dedup-return before detection re-runs or raise `observation_conflict`.

**Resolution (cascades through most findings):** detection is a dedicated, SYSTEM/operator-invoked **reconciliation-detection pass** (`POST /api/v1/reconciliation/detect` + CLI), decoupled from ingest, running in its own transaction(s). It reads current runner-pushed observations (correlated to units via the first-class `subject_type=work_unit` channel), stored lifecycle state, the `unit_pr_binding`, and post-deploy elapsed state; records `reconciliation_conditions` (append-only) for divergence; never mutates a unit; never raises on bad correlation (fail-open). It remains push-only (pure DB reads/writes, no outbound call) and loop-free (invoked on demand, not a background loop).

**This is an explicit deviation from ADR-0002**, which says the orchestrator's "only new logic is conflict-detection **on observation ingest**" — the same language the approved package uses. The deviation is necessary (the three blockers above are not stylistic; in-transaction detection cannot work), it preserves every invariant the ADR protects, and it is surfaced in the design (§1.1, boxed) for Devon's **knowing** approval. ADR-0002's Consequences bullet should be amended to match.

## Confirmed sound (not findings)
- ADR-0002's "invariants constrain the process, not the system" framing is correct; the orchestrator process makes no GitHub/Coolify call on the observation/deploy paths today.
- Workers structurally cannot reach `COMPLETED` (no `WORKER_EDGES→COMPLETED`; only VERIFIER/HUMAN, gated by `completion_satisfied`). No merge edge exists in `LEGAL_EDGES`. AC-011's structural assertions are sound.
- The append-only condition/resolution model (open = no resolution row) matches the existing evidence/adjudication supersession + `reject_append_only_mutation()` trigger pattern.

# Round 2 — independent adversarial re-review of v2

An independent reviewer re-verified every v1 resolution against the code and hunted for flaws *introduced by the fixes*. **All of B-1/B-2/B-3 and M-4…M-11 and m-12…m-18 were confirmed genuinely resolved** (the unique constraint is `(source_system, source_reference, normalized_fact_hash)` with `observed_at` inside the fact identity, so per-snapshot `source_reference` works; `subject_type="work_unit"` is a real enum member; observations are SYSTEM-only; the post-deploy unit's `SUBMITTED` timestamp is readable). The architecture is sound. **Two NEW majors were introduced by the fixes**, both now resolved in v3:

| # | Sev | Finding | Resolution (v3) |
|---|---|---|---|
| **F-1** | MAJOR | **The M-5 fix made AC-004's own scenario unreachable.** `released_at`/`terminal_reason` have exactly one writer — `_perform_reclaim` (`claims.py:251-252`) — so requiring both made recovery reachable *only after* reclaim, and reclaim either mints attempt *n+1* with a live lease (whereupon the newer-evidence guard refuses recovery) or leaves the unit `FAILED` with no route to `SUBMITTED`. Drill #2 as scripted would hit guard refusal. The design also **over-claimed**: it said recovered evidence "can feed the normal verifier→human completion," but `FAILED` has no edge to `SUBMITTED` and only `WORKER_EDGES` reach it (`transitions.py:29`). Package AC-004 only promises **attachment without re-executing the work** — never completion without a new attempt. | Precondition relaxed to the **expired-but-unreleased** claim (`lease_expires_at <= now AND released_at IS NULL`) — the AC's actual scenario. Recovery **releases the claim and SYSTEM-fails the unit without minting a new attempt** (`CLAIMED/EXECUTING→FAILED` are SYSTEM edges), routed through a **shared release primitive** so `released_at` keeps one writer. The false completion claim is **retracted**; the delivered value is that attempt *n+1* short-circuits and **does not redo the work**. Drill #2 rewritten to match. Recovery also takes the `WorkUnit` row lock and re-checks the newer-attempt guard under it. |
| **F-2** | MAJOR | **A fabricated quote was attributed to the binding ADR.** The v2 design and this review both cited ADR-0002 as saying "conflict-detection *driven by pushed observations*" — **that phrase appears nowhere in ADR-0002**, which actually says "on observation ingest," as does the approved package. A real, justified deviation was being papered over with an invented quote, in the two documents gating an irreversible human approval. Threatens AC-012's integrity. | Quote **deleted** from both documents. The deviation is now stated plainly and prominently (design §1.1, boxed; §14), with the three code-level reasons in-transaction detection cannot work, an explicit note that every ADR invariant is preserved, and a request that **Devon approve the deviation knowingly** and that ADR-0002's Consequences bullet be amended. |

### Round-2 minors, all folded into v3
`pass_id` must be strictly monotonic/unique (a reused id with a new timestamp → `observation_conflict`); newest-wins needs the `(observed_at, received_at, id)` tiebreak (`observations.py:123`), not `observed_at` alone (clock skew); detect-pass concurrency is covered by the UNIQUE constraint, and torn reads are avoided by evaluating **only the newest complete pass**; recovery takes the unit row lock + standard idempotency/replay contract; `requeue` reuses the readiness check (`claims.py:464-473`) or the unit lands `READY` unclaimable and invisible; the breaker predicate is `len(failures)+1 >= threshold` **pre-insert**, so the view **calls** the shared function rather than restating the arithmetic; the runner must use a **normalized fact schema** because `SECRET_KEY_PARTS` contains `"log"` and would reject GitHub's `logs_url` outright (`observations.py:33-44`); the `OBSERVATION_SOURCE_SYSTEMS` member for deploy/health facts must be confirmed (an extension is a *listed* migration); split-brain needs **no** runner-pushed deploy observation — the `DeploymentObservation` row already proves the deploy succeeded; and the `retry` human route **already exists** (`/review/units/{unit_id}/retry`, `test_scope_guards.py:78`).

**Round-2 verdict: APPROVABLE-WITH-CHANGES** — the two majors and nine minors above are resolved in v3. The architecture itself was confirmed sound and the v1 blockers genuinely closed.
