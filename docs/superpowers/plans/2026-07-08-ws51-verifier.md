# WS-5.1 Verifier Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an independent verifier layer that evaluates recorded evidence against mapped acceptance criteria, records verifier evidence/adjudications, and drives existing lifecycle outcomes without making workers success authorities.

**Architecture:** Implement a focused verifier service in `src/orchestrator/services/verifier.py`. Reuse existing lifecycle and adjudication services; add a verifier-only evidence append helper so verifier findings can be recorded without worker lease credentials. Expose the service through `POST /api/v1/work-units/{unit_id}/verify` with structured evaluation results.

**Tech Stack:** FastAPI, SQLAlchemy ORM, PostgreSQL, pytest, existing orchestrator service patterns.

## Global Constraints

- Phase 5 WS-5.1 only.
- Do not implement release immutability, artifact digest binding, post-deploy unit creation, tracker canonicalization, brain learning/promotion, graduation automation, automatic merge, automatic deployment, or production infra mutation.
- Do not call GitHub, change-manager, infraops, trackers, brains, web pages, or production infrastructure.
- Do not add new secrets, M2M credentials, env files, or BWS manifest entries.
- Workers must remain unable to record adjudications or verifier findings.
- The orchestrator lifecycle remains canonical; no verifier-run table in WS-5.1.
- Deterministic missing, malformed, stale, untrusted, or insufficient evidence fails closed.
- Judgment-only criteria route to `awaiting_review`.

## File Structure

- Create `src/orchestrator/services/verifier.py`: verifier command/result dataclasses, AC loading, evaluator registry, evidence/adjudication recording, lifecycle transitions.
- Modify `src/orchestrator/services/evidence.py`: add a verifier-only evidence append function that records `evidence.recorded` events without claim/lease credentials and rejects worker use.

- Create `tests/services/test_verifier.py`: deterministic pass, fail, missing evidence, judgment route, idempotency/replay, worker rejection, completion guard integration.
- Create `tests/api/test_verifier_api.py`: route presence, auth role behavior, and response shape.
- Create `docs/operations/verifier.md`: operator behavior, evidence boundaries, idempotency, and non-goals.

def mapped_submitted_unit(
    session: Session,
    *,
    key: str,
    evidence_type: str = "pytest",
    ac_id: str = "ac-1",
) -> WorkUnit:
    revision = register_revision(
        session,
        package_id=f"pkg-{key}",
        source_repository="owner/repo",
        revision=1,
        content_hash=f"sha256:{key}",
        source_path="intent.md",
        source_commit="abc123",
        approved_by=HUMAN.actor_id,
        approved_at=NOW,
        approval_event_id=str(uuid.uuid4()),
        enforcement_snapshot={"acceptance_criteria": [ac_id]},
        authority=AUTHORITY,
        registry_version=1,
        actor_id=HUMAN.actor_id,
        actor_role=HUMAN.role,
    )
    unit = register_approved_unit(
        session,
        revision_id=revision.id,
        unit_key=key,
        title=key,
        outcome=f"{key} complete",
        required_capability="repository_write",
        authority=AUTHORITY,
        max_attempts=3,
        approved_by=HUMAN.actor_id,
        approved_at=NOW,
        actor_id=HUMAN.actor_id,
        actor_role=HUMAN.role,
    )
    criterion = PackageAcceptanceCriterion(
        work_package_revision_id=revision.id,
        ac_id=ac_id,
        condition=f"{ac_id} passes",
        evidence_type=evidence_type,
        evidence="recorded evidence",
        approver="verifier",
    )
    proposal = DecompositionProposal(
        work_package_revision_id=revision.id,
        proposal_number=1,
        state="approved",
        rationale="map unit ACs",
        proposed_by=HUMAN.actor_id,
        proposed_actor_role=HUMAN.role,
        decided_by=HUMAN.actor_id,
        decided_at=NOW,
        idempotency_key=f"{key}-proposal",
    )
    session.add_all([criterion, proposal])
    session.flush()
    session.add(
        ApprovedDecomposition(
            work_package_revision_id=revision.id,
            proposal_id=proposal.id,
            approved_by=HUMAN.actor_id,
            approved_at=NOW,
        )
    )

        DecompositionProposalAcMapping(
            proposal_id=proposal.id,
            package_acceptance_criterion_id=criterion.id,
            unit_key=unit.unit_key,
        )
    )
    unit.state = WorkUnitState.SUBMITTED
    session.commit()
    return unit

def record_worker_evidence(
    session: Session,
    unit: WorkUnit,
    *,
    ac_id: str = "ac-1",
    evidence_type: str = "pytest",
    payload: dict[str, object],
    idempotency_key: str = "worker-evidence",
) -> Evidence:
    unit.state = WorkUnitState.READY
    session.commit()
    grant = claim_unit(session, unit.id, WORKER, f"{idempotency_key}-claim")
    assert isinstance(grant, LeaseGrant)
    transition_unit(
        session,
        TransitionCommand(
            unit_id=unit.id,
            target=WorkUnitState.EXECUTING,
            actor=WORKER,
            expected_version=unit.version,
            idempotency_key=f"{idempotency_key}-start",
            attempt=grant.attempt,
            lease_token=grant.lease_token,
        ),
    )
    evidence = append_evidence(
        session,
        work_package_revision_id=unit.work_package_revision_id,
        work_unit_id=unit.id,
        ac_id=ac_id,
        attempt=grant.attempt,
        actor=WORKER,
        lease_token=grant.lease_token,
        evidence_type=evidence_type,
        stable_ref=f"artifact://{idempotency_key}",
        payload=payload,
        source_revision="abc123",
        idempotency_key=idempotency_key,
    )
    assert isinstance(evidence, Evidence)
    transition_unit(
        session,
        TransitionCommand(
            unit_id=unit.id,
            target=WorkUnitState.SUBMITTED,
            actor=WORKER,
            expected_version=unit.version,
            idempotency_key=f"{idempotency_key}-submit",
            attempt=grant.attempt,
            lease_token=grant.lease_token,
        ),
    )
    return evidence

- [ ] **Step 4: Implement verifier command flow**

Implement `verify_work_unit(session, command)`:

1. Reject non-verifier actors with `DomainError("role_forbidden", ...)`.
2. Lock the `WorkUnit`; load `WorkPackageRevision`; verify state is `submitted` or `verifying`.
3. If submitted, transition to verifying with child key.
4. Load required criteria.
5. For each criterion, call `current_evidence`; evaluate.
6. For deterministic pass, call `record_adjudication(... outcome="passed", evidence_id=evidence.id, ...)`.
7. For deterministic fail/fail-closed, call `append_verifier_evidence(... evidence_type="verifier.finding", payload={...})`, then `record_adjudication(... outcome="failed", failed_evidence_id=finding.id, ...)`.
8. For judgment, do not adjudicate.
9. Pick target: deterministic failure -> `revision_required`; judgment -> `awaiting_review`; otherwise `completed`.
10. Transition to target with child key and current version.
11. Return `VerifierResult`.
